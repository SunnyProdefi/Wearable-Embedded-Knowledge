## 1. 先区分时钟源与时钟信号

| 名称 | 作用 | 边界 |
|---|---|---|
| Crystal，晶体 | 与振荡电路配合形成参考 | 普通无源晶体不等于完整有源时钟发生器 |
| Oscillator，振荡器 | 产生周期性信号 | 可为片内电路或独立器件，精度/启动条件依设计 |
| PLL，Phase-Locked Loop，锁相环 | 使反馈信号与参考保持关系，用于频率合成等 | 锁定、输入范围、倍分频和切换要求查具体实现 |
| Divider / Mux / Gate | 分频、选择来源、允许或阻止时钟传递 | 配置顺序和共享影响不可忽略 |

Clock Tree 是时钟依赖与分配关系。以下是教学逻辑图，不是实际芯片拓扑：

```text
参考源 → PLL/其他源 → 来源选择 → 分频 → 门控 → 模块/输出引脚
```

对简单整数分频，`fout=fparent/N`；PLL 可以有多种整数或小数关系，不用一个公式概括全部硬件。请求某频率可能被框架舍入、拒绝或受父节点约束。

## 2. Camera 中的时钟名字不能互换

- MCLK 常指提供给 Sensor 的外部参考输入，不能据此直接等同于帧率、像素吞吐或 CSI lane 速率。
- Sensor 内部可能按输入与配置生成采样/输出时序；具体关系查手册。
- PCLK 在并行图像接口语境中常指像素数据采样相关时钟；不能假设每个 CSI-2 设计都有同名外部引脚。
- SoC 控制器的总线/功能时钟与引脚上发出的 SCL 或串行数据时钟，属于不同层级。

修改其中一路可能影响其他使用者；“降低 CPU 主频”也不保证已降低 Camera 或音频所依赖的各路时钟。

## 3. 配置、锁定、输出与可用分别验证

| 证据 | 可以支持什么 | 不自动支持什么 |
|---|---|---|
| 驱动请求频率成功 | 框架接受了对应操作 | 引脚已输出或精度满足器件要求 |
| PLL 显示锁定 | 相应状态定义下的锁定条件成立 | 下游 mux/gate、引脚复用和负载连接正确 |
| 负载端测到频率 | 该测点有相应周期性活动 | 占空比、幅度、抖动和启动时序全部合格 |

Linux CCF 用父子关系和硬件回调管理时钟；prepare/enable、set rate 和共享引用有各自契约，不能绕过框架随意写共享控制寄存器。[Linux v6.8 CCF](https://www.kernel.org/doc/html/v6.8/driver-api/clk.html)
软件读取的 rate 通常来自框架/硬件模型，不应当作高精度物理测量值。

## 4. Clock Gating 与 Power Gating

Clock Gating 停止某些时钟活动，常用于减少动态功耗，但不保证供电被切断、寄存器丢失或模块所有活动都停止。
Power Gating 关闭指定电路的供电，通常涉及隔离、保留、复位及恢复。两者都要协调当前消费者和在途事务。
开关时钟不自动完成数据同步；睡眠时能否响应外部事件，还取决于保留的检测/唤醒路径。
智能眼镜要对齐 Sensor、接收端和存储依赖；TWS 还关注音频采样时钟与流连续性，不能无协议地切换正在使用的时钟源。

## 5. 模拟问题：时钟频率日志正确，Sensor 仍不应答

类型：模拟，无已确认根因。依次核对资源对应的时钟节点、父源有效/锁定、下游分频/门控、引脚复用、负载端信号及 Sensor 所需时序，同时保留供电、复位与总线分支。
观测要说明测点、触发时刻和测量负载；探头接在振荡节点与普通时钟输出引脚不是同一种条件。
若下游无输出，不能直接改 PLL；如果频率不匹配，也不能假定只改 MCLK 就能匹配任意传感器模式。修正必须回到实际时钟树和器件支持配置。
