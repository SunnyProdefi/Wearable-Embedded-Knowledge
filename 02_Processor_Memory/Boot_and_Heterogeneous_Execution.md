## 1. 启动不是一次函数调用

Boot 是系统从复位状态走向可执行目标任务的过程。Firmware 是运行在设备/处理器上的固件；它可以包含裸机程序或 RTOS，也可以由其他处理器加载。Bootloader 是承担加载、初始化及控制转交等职责的启动软件，二者分类并不互斥。

典型教学流程如下，不是所有产品必须存在的固定阶段：

```text
复位后到达平台定义的入口
→ BootROM/启动代码选择启动源，按平台要求验证或装载镜像
→ 必要硬件与运行环境准备
→ 转交到后续 Bootloader、OS 或 Firmware
→ 驱动和服务初始化
→ 对外宣告指定功能就绪
```

某些 MCU 从片内 Flash 直接启动，某些 SoC 先在片内 SRAM 运行早期代码再初始化 DDR。启动源、镜像校验、加载方式和跳转条件必须查实际平台；不能把一种平台的多级加载流程套给所有 MCU。

## 2. 存放位置不等于执行位置

结合 [S1-02](Memory_and_Address_Spaces.md) 和 [S1-07](Cache_MMU_and_DMA_Mapping.md)，检查四类位置：

| 对象 | 要确认的条件 |
|---|---|
| 固件镜像 | 存在哪种介质、由谁读取、版本与格式是否匹配 |
| 指令与只读数据 | CPU 从哪里取指，加载执行还是 XIP，映射/Cache 属性是否正确 |
| 栈、堆与全局变量 | 位于可用 SRAM/DDR 的哪一段，初始化、边界和生命周期是否正确 |
| DMA/共享 Buffer | 设备和其他核能否访问，地址视图、所有权与同步是否匹配 |

在典型 C/C++ 运行环境中，启动代码还会按链接布局准备栈、初始化已初始化数据和清零相应区域；实际由 ROM、Bootloader、运行时谁完成，要检查工具链及启动代码。
“固件已经下载”只证明某个传输阶段，不能自动证明入口正确、运行环境完成或外设服务可用。

## 3. 异构系统中，每个核都有自己的前提

异构执行（Heterogeneous Execution）是在不同类型处理器上分配任务。教学例：AP 运行 Linux，MCU 运行 RTOS；它们可位于同一 SoC，也可在不同芯片。

```text
AP：准备远端资源/镜像 → 请求启动 MCU → 等待 MCU 的协议就绪
MCU：启动运行时 → 初始化自身资源 → 发布版本/能力/就绪状态
双方：建立消息与共享内存契约 → 执行具体任务
```

这是逻辑协作图，不规定谁必须启动谁。MCU 也可能独立启动，AP 晚于它运行。
共享同一颗芯片不等于共享地址空间，更不等于所有存储在各低功耗状态都可用。跨核要约定消息格式、请求编号、超时、重启代次、共享区域、访问者和释放条件。

Linux remoteproc 可抽象远端处理器的装载和启停。具体硬件控制由平台实现；`rproc_boot()` 的成功不能被调用方自行扩大解释为任意 Camera 服务已经就绪。[Linux v6.8 remoteproc 原始文档](https://raw.githubusercontent.com/torvalds/linux/v6.8/Documentation/staging/remoteproc.rst)

## 4. 用阶段证据判断启动到了哪里

| 已有证据 | 可以支持什么 | 还需确认什么 |
|---|---|---|
| 镜像加载完成 | 指定装载步骤完成 | 目标地址、镜像完整性、入口与启动条件 |
| MCU 心跳正常 | 该心跳路径正在运行 | 其他代码/数据路径、外设和共享内存可用 |
| 服务 READY | 协议定义的服务条件成立 | 能力/版本、资源状态是否覆盖当前任务 |
| Camera 请求完成 | 对应任务获得结果 | 本轮数据有效、错误与 Buffer 交接 |

就绪状态要定义对应功能和有效期。远端重启、掉电或资源切换后，旧 READY 与旧完成通知不能当作新代次证据。

## 5. 模拟问题：MCU 有心跳，却在读取 DDR 时失败

类型：模拟，无实测根因。假设心跳代码及所需数据位于可用 SRAM，而待访问图像位于 DDR。

| 假设 | 验证证据 |
|---|---|
| 仅心跳运行，不代表全部运行环境可用 | 链接布局、实际 PC/栈、失败调用所在阶段 |
| DDR 当前未供电、初始化或恢复完成 | 对应电源/时钟/内存控制器状态与恢复记录 |
| MCU 地址视图或权限不同 | 双方地址窗口、共享区域及访问属性 |
| Buffer 已复用或数据未同步 | 请求代次、Buffer 生命周期、交接记录 |

先定位出错阶段，再验证分支；不以“MCU 固件没烧好”作为唯一结论。候选修正包括等待资源就绪、修正共享视图、将确需常开的工作集放入可用存储，但都要按证据选择。
如果要求低功耗采图，还必须具备 Sensor、接收端、写内存通路、存储和通知的完整依赖，仅 MCU 能执行不能证明能采图。

## 理解检查

1. 固件镜像加载成功、MCU 有心跳，为什么仍不能保证 MCU 可以读取 AP 交来的 DDR 图像？至少说明三类条件。
2. 某功能要求主 DDR 关闭时仍能运行，除代码放 SRAM 外，还要检查哪些代码/数据和外设依赖？
